# 群友好感度（实验性功能）

该功能可能存在不稳定性与误判，仅供群聊娱乐，不表示真实心理状态。默认关闭。

## 使用与配置

在 AstrBot 插件配置的「群友好感度（实验性功能）」二级菜单开启总开关。

- `/查看好感度 @群友`（`/affinity`）：查看**对方 → 你**的分数。
- `/调整好感度 @群友 70`（`/setaffinity`）：设置**你 → 对方**的分数为 70，范围 0～100。
- `/调整好感度 @群友 +5` 或 `-5`：相对调整你对对方的分数，结果限制在 0～100。
- 没有有效证据或手动调整时，返回「未查询到好感度数据」，提示互相交流、引用回复或使用求婚。
- 新命令沿用插件的关键词触发开关，并支持 QQ 官方机器人紧贴文本提及的命令形式。
- 查询与调整回复优先使用群名片，其次群昵称或已缓存昵称；成员查询设有3秒超时，无法获取昵称时使用「这位群友」，不显示「用户(账号)」。查询展示好感度与最近双向交流天数，详细计分分项保留在 debug 日志中。
- 私聊不采集；全局群黑白名单和好感度独立群黑白名单对采集、情绪分析、查询、调整和游戏事件均生效。

### 好感度独立群黑白名单

在「群友好感度（实验性功能）」菜单中设置 `whitelist_groups` 与 `blacklist_groups`，每项填写一个群 ID，两项默认都为空。

1. 先检查插件顶部原有的**全局**群黑白名单：全局黑名单禁止，全局白名单非空时只有名单内群可通过。
2. 通过全局检查后，再检查好感度名单：好感度黑名单禁止；好感度白名单非空时只允许名单内群。
3. 两层都允许，才能使用好感度；同一层的黑名单都优先于白名单。

例如，全局允许群 A、B，好感度白名单只填 B，则 A 仍可抽老婆、求婚等，但不采集、查询或修改好感度。把全局禁止的群 C 填进好感度白名单，也不能让 C 使用该功能。

修改名单后，已排队的消息和模型任务会再次检查权限；取消授权的群不再新增好感度证据。已有历史不因修改名单立即删除，仍按60天留存规则清理。名单不改变通用模型缓存的保留策略。

### 不启用小模型

只根据明确的 @、引用回复、双方持续交流和插件游戏事件计算。不会下载模型或安装额外依赖。
普通群消息只用于后续引用消息的发送者查找，本身不会产生好感度记录。不能确定对象、多人提及、纯 @、机器人消息和插件命令不用于定向计分。
仅分析启用后收到的消息，不会自动拉取历史聊天。

### 启用小模型情感分析

总开关和「启用小模型情感分析（自动下载）」同时开启后，后台自动：

1. 在插件数据目录 `affinity_model/runtime/` 创建独立 Python 虚拟环境。
2. 从默认清华 PyPI 镜像安装 `onnxruntime`、`tokenizers`、`numpy` 的 CPU 二进制依赖，不更改 AstrBot 的依赖。
3. 优先从 `https://huggingface.co` 官方源下载固定版本的量化 ONNX 模型（约 136MB）及分词文件（约 3MB），失败后自动切换镜像，支持跨源断点续传，临时文件校验成功后原子替换。
4. 在独立子进程中通过 CPU 推理，线程数限制为 1。模型常驻复用，不会逐条重新加载。

**无需访问 GitHub、手动启动模型服务或填写付费 API。**优先备用模型镜像和 PyPI 镜像地址可以修改，要求使用不含账号和查询参数的 HTTPS 地址。依赖、虚拟环境还会额外占用磁盘与内存；模型权重大小不等于实际运行内存。

为了自动安装和兼容性，使用支持中文的多语言三分类蒸馏模型，而非之前讨论的旧 PaddleHub TextCNN：

- [模型说明](https://huggingface.co/lxyuan/distilbert-base-multilingual-cased-sentiments-student)（基础模型声明 Apache-2.0）。
- [量化 ONNX 权重](https://huggingface.co/Xenova/distilbert-base-multilingual-cased-sentiments-student)。
- 固定 revision：`9d9ac661fd7b0b48535a1fc99b20ae6947629e65`。
- 权重用 SHA-256 校验；分词文件用固定 Git blob 哈希校验。

开启开关即允许下载模型和独立运行依赖；聊天推理完全本地进行，不上传聊天内容。安装要求 Python 支持 venv/pip，系统有对应 CPU 依赖 wheel、足够磁盘并能连接镜像。失败或平台不支持时保留基础计分，一小时后重试，原因输出到 AstrBot 控制台。关闭开关后停止准备任务并释放模型进程，缓存文件保留供下次使用。

模型默认按以下顺序自动尝试：官方 `https://huggingface.co` → `https://hf-mirror.com` → `https://aifasthub.com` → `https://hf-mirror.net`。配置的「模型优先备用镜像地址」会放在官方源之后，其余内置镜像依次补充并去重。每个文件独立选择可用来源，切换来源保留部分下载文件，最终仍必须通过固定版本哈希校验。备用镜像的可用性会随地区、网络和时间变化，配置文件可下载也不保证整个权重始终可下载。不要将模型源地址填写到 PyPI 依赖镜像配置中。

下载进度不依赖 debug 开关，每增长约 10% 或传输持续约 15 秒输出一条简短进度，包含百分比、已下载/总 MiB；当前来源、切换原因、续传和校验也会显示。遇到 HTTP 401/403/404 立即放弃当前源；遇到 429 且还有备用源时直接切换，不继续请求被限流的源。最后一个源的 429 采用退避等待，优先尊重 `Retry-After`；服务器要求等待超过 60 秒时结束本轮。所有来源都失败后保留基础计分，一小时后重新尝试。

模型未就绪时不会重放历史消息或事后补算全部情绪；当时的互动证据仍正常保存。消息队列最多 256 项，情绪队列最多 32 项，繁忙时跳过额外处理，避免阻塞命令。

## 计分规则 v1

分数基准为 30，**没有证据时不显示这个基准分**。自动分数从最近 60 天的证据重新计算，限制在 0～100。

### 熟悉度

一条消息不立即发放固定分数：先形成定向互动观测，再按 UTC 日期汇总双方互动。

- 同方向、同一对用户，10 分钟内最多保留一次观测；24 小时内重复文本也不增加观测。
- 只有同一天双方都出现有效回应，才产生共享的熟悉度贡献。
- 每日贡献同时考虑双方是否均衡、观测数量是否达到上限。跨天积累比一天刷屏更有价值。
- 熟悉度贡献上限 30 分，半衰期 30 天。

### 情绪倾向

小模型只分析当前发言正文，不分析被引用的原文。积极/消极概率不会直接转换成好感度。

- 明确指向人的感谢、支持等表达，且积极概率至少 0.75，才记录正向证据。
- 明确指向人的排斥表达，且消极概率至少 0.8，才记录负向证据。
- 吐槽食物、工作、自己的遭遇，以及反讽对象不明的内容保持中性。
- 同方向一天至少两次有效情绪观测才产生贡献；每日限制在 ±2，累计限制在 ±20，半衰期 14 天。

这是保守启发式，仍可能误判，也会漏掉隐含表达；它不是完整的人际语义理解。

### 戳一戳

支持 OneBot/aiocqhttp 群聊的 `Poke` 消息段（含旧版 `qq` 目标字段）及 `notify/poke` 通知。A 戳 B 只产生 A 对 B 的轻量关注贡献，不自动增加 B 对 A 的分数，也不触发小模型。

- 普通模式每次有效戳一戳贡献 +0.1；同一方向30分钟内最多计一次。
- 同一对群友不分方向，滚动24小时内最多计三次；重复事件不会重复计入，重载插件也不会重置限额。
- 独立于正常 @ / 引用的去重，不占用正常聊天的观测机会；互戳不会被当作双向聊天天数。
- 贡献半衰期14天、累计上限3分；激进模式仍乘以1.6，所有观测最多保留60天。
- 私聊、戳自己、涉及当前机器人、目标缺失或不明确均跳过；遵守全局和好感度两层群黑白名单。

### 游戏事件

- A 向 B 求婚成功：A → B、B → A 各产生 +5 的事件。
- A 强娶 B 成功：只产生 A → B 的 +2 事件；不会增加 B → A。
- A 的求婚被 B 明确拒绝：滚动 7 天内前两次不扣分，第 3 次起小幅降低 B → A，每次 -0.5。
- 求婚超时、取消、因冷却失效不算拒绝。
- 每对关系每日游戏加分最多 +8，扣分最多 -2；游戏贡献总计限制在 -10～+30，半衰期 30 天。
- 每次求婚以原始请求 ID 去重，强娶以消息 ID 去重，抽到某人不计主动好感。

「激进判断」将以上自动贡献乘以 1.6，正负都放大；不降低判断门槛，也不直接放大手动设置值。

### 手动调整

只允许修改发送者自己的出向关系。绝对设分保存相对于当前自动分数的修正量，相对加减先读取当前值再更新修正量；不会修改对方的反向关系。修正半衰期 45 天，自动变化仍可继续影响结果。查询不产生贡献、不延长数据寿命。

## 数据库与留存

使用插件数据目录下已有的 `wifepicker.db`，不迁移或修改旧 JSON 数据及 `proposal_events` 表。范围统一使用：

`平台实例 ID + 机器人 ID + 群 ID`

| 表 | 保存内容 | 限制 |
| --- | --- | --- |
| `affinity_messages` | 消息 ID、发送者 ID、当前正文、收到时间 | 每群每日最多 2,000 条，每条最多 512 字符；不存图片、附件、引用正文或昵称 |
| `affinity_interactions` | 消息 ID、来源、目标、正文哈希、引用/提及/戳一戳类型、情绪贡献、时间 | 双向分别记录；聊天去重，戳一戳独立冷却和上限 |
| `affinity_game_events` | 事件 ID、同意/拒绝/强娶、操作者、对象、时间 | 原始事件幂等去重 |
| `affinity_manual` | 来源、目标、手动修正量、设置时间 | 每个方向仅保留最新一条 |

**四张表全部按记录时间保留最多 60 天的有效数据。**启动及每小时清理过期行，关闭功能后仍维护已有数据库；查询始终排除超过 60 天的数据，即使定时清理尚未执行。没有跨期永久累计的好感度快照。SQLite 删除后会复用空闲页，文件体积不会每次删除后立刻缩小。

模型权重和运行环境属于可复用程序缓存，不是群聊历史，不随 60 天清理删除。

## 日志与验证

运行日志全部通过 AstrBot 的 `logger` 输出。开启插件已有的 `debug_enabled` 后，在控制台 INFO 级别显示：

- 范围、消息 ID、发送者、候选对象、引用查找、入队长度。
- 不采集/不计分原因、10 分钟与重复文本去重结果。
- 游戏事件方向与去重键、查询分项、手动调整方向与结果。
- 镜像地址、独立依赖安装输出、下载阶段与进度、校验、CPU 推理耗时和概率。
- 60 天清理数量、队列拥塞、安装/推理失败与回退状态。

默认不输出完整聊天正文。关闭 debug 时仍显示模型安装阶段、下载进度、错误回退和实际过期数据清理。

验证：`python -m unittest discover -s tests -p test_affinity.py -v`。测试使用临时 SQLite、模拟平台事件和模型故障，不会下载模型，也不需要运行 AstrBot 服务。
